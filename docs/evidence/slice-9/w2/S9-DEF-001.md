# S9-DEF-001 — ראיית תוצאות Auth typed ושחזור מקומי

תאריך: 26.8.2026

סביבה: Supabase ו־Mailpit מקומיים בלבד. לא נשלח Email אמיתי, לא נקרא secret,
לא נשמרו כתובת callback רגישה, סיסמת בדיקה, token, cookie או פרטי ספק בראיה.
Playwright רץ עם trace, screenshots, video ו־DOM error snapshots כבויים.

## שינוי שנבדק

- `forgotPasswordAction` מחזיר union typed. הצלחה ו־unknown address שקולות;
  cooldown ו־provider outage הן תוצאות actionable נפרדות.
- `/auth/confirm` קורא רק `error_code`, ממפה invalid, expired, reused,
  session/PKCE mismatch ו־provider unavailable לסטטוסים allowlisted ואינו מחזיר
  `error_description` או הודעת SDK.
- הצלחה מוצגת ב־`role="status"`; כשל actionable ב־`role="alert"`.
- digest SHA-256 קצר־חיים ב־cookie `HttpOnly` שמוגבל ל־`/auth/confirm` מזהה
  replay מיידי של אותו callback באותו דפדפן. הוא diagnostic בלבד, אינו מכיל
  את הקוד הגולמי ואינו גבול הרשאה.
- עדכון סיסמה מוחק את marker הייעודי, מסיים את ה־session המקומי ודורש login
  מחדש.

## regressions שהיו נכשלים ללא התיקון

ה־spec החדש `src/features/auth/auth-flow-results.test.ts` כולל את התרחישים:

1. `returns the same account-neutral result and public copy for success and an unknown address`
2. `maps a cooldown response to a stable actionable result` עבור code ו־HTTP 429
3. `maps provider failure to retry-later without exposing details`
4. `maps $expected without provider copy` עבור invalid, expired, reused,
   cross-browser/PKCE ו־outage
5. `allowlists query-string presentations and marks failures as alerts`

המימוש הקודם התעלם מכל error של `resetPasswordForEmail`, הציג success גם ב־
429/outage, מיפה כל כשל exchange ל־browser mismatch, והציג status שהגיע מה־URL
בסמנטיקת success/info. הבדיקות לעיל היו נכשלות מולו.

התרחיש הקיים שהורחב, `e2e/auth.spec.ts` —
`completes signup, confirmation, profile, logout, login and recovery`, מוכיח:
unknown/known copy זהה → Mailpit delivery → cross-browser mismatch בטוח → בקשה
חדשה ו־callback באותו דפדפן → password update → replay של אותו callback נדחה
כ־`recovery-link-reused` → session סגור → הסיסמה הישנה נדחית → החדשה מתקבלת.
ה־callback נשמר רק בזיכרון התהליך ואינו נכנס ל־report.

## גבולות הראיה

- המיפוי של 429/outage נבדק ברמת Vitest עם errors סינתטיים בטוחים. Supabase
  המקומי לא החזיר 429 באופן דטרמיניסטי לאחר replay מיידי, ולכן אין כאן טענת
  E2E ל־rate limit מקומי.
- אין כאן claim על delivery, rate limit, callback, SMTP או account ב־Hosted.
  אלה נשארים `OWNER_ACTION_REQUIRED` תחת `S9-DEF-004`.
- commit המימוש שנבדק:
  `4a500fef8a728cb13092a02040aeb694ae6f2a55`. הוספת ה־SHA לפנקס ולראיה נעשית
  ב־commit תיעודי עוקב ואינה משנה את תוצאות ההרצה המתועדות כאן.
