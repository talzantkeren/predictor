## חלוקת הפעולה שנותרה

**קלט owner שנותר:** לאחר ה־merge למסור מחוץ ל־Git כתובת מדויקת שנמצאת כבר
ב־Supabase organization ובחשבון Auth מוכר, ושייכת לתיבה שאינה מבצעת prefetch
של קישורים חד־פעמיים. לפני השליחה נדרש אישור נקודתי חדש; לאחריה ה־owner מחזיר
את הקישור מן inbox. אין צורך ב־SMTP credential.

**פעולת agent לפני merge:** הסתיימה. delivery נצפה, וה־owner דיווח על מעבר
same-device מלא של callback, עדכון סיסמה, replay denial ו־old/new login. זו
אינה ראיית agent-observed ואינה מחליפה את capture ה־final-SHA המלא.

**פעולת agent לאחר merge:** להסיר דרך URL Configuration רק את שני entries
ההיסטוריים, בלי לקרוא secret, ולצלם מחדש את כל הראיה על final SHA. באותו
browser/session להריץ בחשבון disposable:
   signup/confirmation לפי הצורך → בקשת recovery לכתובת מוכרת ולכתובת שאינה
   מוכרת עם copy שקול → delivery → callback → session → password update →
   replay denied → logout → old password denied → new password login.
1. ליצור cooldown מורשה בלי לפגוע בנמענים אחרים ולאמת ש־429 מוצג כ־alert
   actionable. לא לשנות rate limit כדי לגרום לבדיקה לעבור ולא לשמור raw header.
2. לתעד רק final SHA, origin/path ללא query, UTC timestamps, שם מנגנון delivery,
   scopes בטוחים, קודי תוצאה allowlisted ותוצאות PASS/FAIL. אין לתעד Email,
   סיסמה, token, cookie, confirmation URL מלא, provider response או screenshot
   שמכיל מידע כזה.
3. להריץ שוב `npm run test:e2e` מקומית ולצרף ראיה נפרדת tied ל־final SHA.
