# S9-DEF-004 — שער Auth ו־Email ב־Hosted

תאריך: 26.8.2026

סטטוס: **OWNER_ACTION_REQUIRED — אינו PASS**.

כל הנדסת ה־Auth העצמאית וה־Mailpit E2E בוצעו תחת `S9-DEF-001`. אין בסביבה
הזמינה credential מאושר של SMTP/חלופת delivery, כתובת disposable שבעליה אישר
את השימוש, או הרשאה לבצע ולתעד signup/recovery ב־Hosted. בהתאם ל־INV-05 לא
הומצא ספק, לא נרכשה תכנית, לא בוצעה mutation ולא נקרא/הודפס secret.

## עובדות מסוננות שניתן לקבע ללא mutation

- Production origin/Site URL הקנוני: `https://predictor-swart.vercel.app`.
- Production callback הקנוני:
  `https://predictor-swart.vercel.app/auth/confirm`.
- Local origin הקנוני: `http://localhost:3000`; callback:
  `http://localhost:3000/auth/confirm`.
- loopback חלופי, רק כאשר הוא origin ההרצה שנבחר במפורש:
  `http://127.0.0.1:3000/auth/confirm`.
- Preview Auth הוא QA פנימי אופציונלי ולא דרישת קורס. ה־Preview של PR #14
  נבדק כ־public smoke בלבד; אין כאן claim שה־callback שלו allowlisted.
- snapshot הקריאה של audit PR #13 מ־26.8.2026 תיעד Site URL של Production,
  local callback, Production callback ו־aliases ישנים של Slice 1/3; לא היה בו
  custom SMTP. ה־sender המובנה היה team-only/best-effort עם מכסה project-wide
  של שתי הודעות לשעה, ולכן הוא אינו מוכיח arbitrary-recipient delivery.
- metadata מסונן של Vercel מציג את שמות משתני ה־Production/Preview הצפויים אך
  אינו מספק credential ל־SMTP או disposable recipient. ערכי variables לא
  נקראו ולא נשמרו.

ה־snapshot הוא עובדה היסטורית של audit ולא טענה ש־Hosted Auth נקרא מחדש לאחר
commit המימוש. README עודכן כך שאינו מבטיח Auth ב־aliases ישנים או ב־Preview
הנוכחי.

## פעולה מדויקת לבעלים

1. לאשר בכתב כתובת disposable שאינה חשבון אישי/Production ו־custom SMTP או
   מנגנון delivery קיים ומאושר שמסוגל לשלוח לנמען שרירותי. לשמור credentials
   רק ב־Supabase Dashboard/secret store — לא ב־Git, PR, terminal output או
   evidence.
2. ב־Authentication → URL Configuration להשאיר Site URL ו־Production callback
   בדיוק כמתועד לעיל, לשמור את Local callback המדויק, ולהסיר aliases/
   wildcards היסטוריים רק לאחר אימות שאין להם צרכן. אם נדרש Preview QA פנימי,
   להוסיף callback מדויק אחד של branch alias הפעיל; לא wildcard.
3. על SHA המועמד הסופי, באותו browser/session, להריץ בחשבון disposable:
   signup/confirmation לפי הצורך → בקשת recovery לכתובת מוכרת ולכתובת שאינה
   מוכרת עם copy שקול → delivery → callback → session → password update →
   replay denied → logout → old password denied → new password login.
4. ליצור cooldown מורשה בלי לפגוע בנמענים אחרים ולאמת ש־429 מוצג כ־alert
   actionable. לא לשנות rate limit כדי לגרום לבדיקה לעבור ולא לשמור raw header.
5. לתעד רק final SHA, origin/path ללא query, UTC timestamps, שם מנגנון delivery,
   scopes בטוחים, קודי תוצאה allowlisted ותוצאות PASS/FAIL. אין לתעד Email,
   סיסמה, token, cookie, confirmation URL מלא, provider response או screenshot
   שמכיל מידע כזה.
6. להריץ שוב `npm run test:e2e` מקומית ולצרף ראיה נפרדת tied ל־final SHA.

עד שכל ששת הצעדים בוצעו ונצפו, `S9-DEF-004` נשאר
`OWNER_ACTION_REQUIRED`; הוא אינו `VERIFIED`, אינו waiver ואינו ראיית release.
