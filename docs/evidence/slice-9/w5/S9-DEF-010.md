# S9-DEF-010 — due-aware Sync fairness

Status: `VERIFIED`

## Implemented contract

`claim_sports_sync` still performs actor validation, lease serialization,
expiry recovery, provider backoff and force cooldown before planning. Among the
remaining due kinds it now selects the least-recently attempted fenced claim
from `sync_runs`; a failed claimed run participates, while a generation-less
`CONCURRENT_ATTEMPT` does not. Consequently targeted, catalog and
reconciliation are each selected within at most three consecutive eligible
claims. No queue, second Cron, provider request or public write grant was added.

Targeted selection orders `live` before stale/near-live, then kickoff and
external ID, with the existing cap of 20. The 12-hour catalog, 6-hour
reconciliation and one-minute targeted due intervals remain unchanged.
`NOT_DUE`, provider backoff and active-lease behavior retain their existing
no-work contracts.

## New regression names

- `current live is first and retained when more than twenty stale fixtures compete`
- `overdue catalog is served on the second eligible claim despite constant targeted work`
- `overdue reconciliation is served within the three-claim fairness bound`
- `fair rotation retains monotonic generations and unique fencing tokens`
- `each selected plan finalizes through the unchanged fenced contract`
- `a genuine no-due state returns no work plan`
- `genuine NOT_DUE persists no run for the provider orchestrator to call`
- `fair selection never bypasses durable provider backoff`
- the orchestrator `NOT_DUE` regression now also requires no `finalize` call.

The sequential fairness suite fails on the preceding targeted-first planner:
catalog and reconciliation are never selected while targeted work remains due,
and a live fixture can be absent from the oldest-kickoff cap.
