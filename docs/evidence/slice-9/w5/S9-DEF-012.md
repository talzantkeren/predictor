# ראיית מסירה — S9-DEF-012

## סטטוס

`OWNER_ACTION_REQUIRED` — המימוש המקומי וה־regression הושלמו, אך תנאי הקבלה
דורש response מתוזמן ומסונן מ־Hosted לאחר deploy של ה־candidate. לא שונה
Hosted Supabase ולא נקרא/הודפס secret במהלך המסירה הזאת.

הסיכון נשאר P3 ולא קודם ל־P2: slow path מבוקר הסתיים ב־failure סופי עם
finalize יחיד; לא נצפו truncation, ‏orphan lease, ‏finalization חסר או כפול.

## חוזה שמומש

- provider client: ‏30,000ms.
- `pg_net.timeout_milliseconds`: ‏45,000ms, עם יותר מ־10s margin מעל ה־client.
- Next.js Route: ‏`maxDuration=60` שניות.
- fencing lease: ‏120 שניות.
- job יחיד בשם `predictor-sports-sync`; migration שומרת schedule, active state,
  target, Vault lookup ו־headers בלי להחזיר או לרשום את ה־command.
- job חסר ב־Local/CI הוא no-op; כפילות או timeout pattern לא מוכר נכשלים סגור.

תקרת 60 שניות נתמכת גם ב־Hobby ללא Fluid compute לפי מסמך Vercel הרשמי שנבדק
ב־27.8.2026:
<https://vercel.com/docs/functions/configuring-functions/duration>.

## Regression חדש

- `POST /api/cron/sync > keeps the route ceiling above the provider budget with margin and below the lease`
- `shared sports sync orchestration > finalizes exactly once after a controlled slow default retry path`
- pgTAP: `45s pg_net timeout has margin over the 30s app budget and remains below the 60s route and 120s lease`
- pgTAP: `rename preserves schedule, active state and target while changing only the timeout`
- pgTAP: `reapplying the aligned configuration is idempotent`
- pgTAP: `alignment preserves a disabled job and its non-default schedule`
- pgTAP: `configuration fails closed instead of mutating duplicate scheduled jobs`
- pgTAP denial אמיתי ל־anon ול־service_role עבור schedule ו־`cron.job`.

## פעולת owner מדויקת לאחר deploy

1. להשאיר את PR #14 במצב Draft ולא למזג במסגרת פעולה זו. לאחר deploy מאושר של
   candidate שמכיל את migration ‏`20260827170000`, להחיל migrations בדרך
   המאושרת בלבד. אין להשתמש ב־`db reset --linked` ואין לפתוח command/headers.
2. ב־Supabase SQL Editor להריץ רק את השאילתה המסוננת הבאה. היא אינה בוחרת
   `command` ואינה חושפת Vault value:

```sql
select jobname, schedule, active,
       command ~ 'timeout_milliseconds[[:space:]]*(=>|:=)[[:space:]]*45000([^0-9]|$)'
         as timeout_is_45s
from cron.job
where jobname in ('predictor-slice7-manual-sync', 'predictor-sports-sync');
```

   נדרש בדיוק row אחד: `predictor-sports-sync`, ‏`active=true`,
   `timeout_is_45s=true`; אין job ישן או כפול. אם אין row, להגדיר את job היחיד
   דרך Dashboard/Vault בלי להעתיק secret ל־SQL ואז להריץ
   `select private.configure_predictor_sync_cron();` פעם אחת.
3. להמתין ל־tick מתוזמן שמחזיר `data.runId` לא־ריק (לא לשנות נתוני Production
   כדי לכפות due), ובתוך חלון השמירה של `pg_net` להריץ את השאילתה המסוננת:

```sql
with scheduled_response as (
  select response.id as request_id,
         response.status_code,
         response.timed_out,
         response.created,
         response.content::jsonb as body
  from net._http_response as response
  where response.created >= clock_timestamp() - interval '6 hours'
    and response.content_type like 'application/json%'
    and response.content ~ '"runId"[[:space:]]*:[[:space:]]*"[0-9a-f-]{36}"'
)
select response.request_id,
       response.status_code,
       response.timed_out,
       response.created,
       run.id as run_id,
       run.status,
       run.finished_at,
       lease.run_id is null as lease_released
from scheduled_response as response
join public.sync_runs as run
  on run.id = (response.body #>> '{data,runId}')::uuid
join public.sync_leases as lease
  on lease.provider = run.provider
order by response.created desc
limit 1;
```

4. לשמור בראיה רק את שמות העמודות והשורה המסוננת: status HTTP, ‏timed_out,
   request timestamp, ‏run UUID, ‏terminal status, ‏finished_at ו־lease_released.
   נדרש `timed_out=false`, ‏run ב־`succeeded` או `failed`, ‏`finished_at` לא־null,
   ו־`lease_released=true`. אין לשמור response content, URL, headers, command,
   cookies, actor, secret או provider payload.
5. אם נצפים response truncation, orphan lease, finalization חסר או כפול — לעצור
   ולקדם את הרשומה ל־P2 defect עם הפלט המסונן. אחרת לצרף את הראיה, לשנות את
   הרשומה ל־`VERIFIED`, ולעדכן את SHA של ה־candidate שנפרס.
