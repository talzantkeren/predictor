# S9-DEF-025 — OWNER_ACTION_REQUIRED

## מצב

`OWNER_ACTION_REQUIRED` ב־27 באוגוסט 2026. ממצא ה־audit המחייב קובע כי
`SPORTS_API_KEY` עדיין משויך ל־Production+Preview, אף ש־Preview משתמש ב־Manual.
לא בוצעה קריאה חוזרת לערך, לא בוצע `vercel env pull`, ולא שונה Vercel מרחוק.
הסרת scope והמרה ל־Sensitive עשויות לדרוש הזנה מחדש של credential, ולכן רק
owner שמחזיק אותו רשאי לבצע אותן.

המדיניות המסונכרנת במסמכי המאגר היא:

| שם | Production | Preview | Local/CI |
| --- | --- | --- | --- |
| `SPORTS_API_PROVIDER` | `api-football` | `manual` | `manual` |
| `SPORTS_API_KEY` | present, Sensitive | absent | absent |

הטבלה היא היעד המאושר, לא ראיה שה־Hosted configuration כבר שונה.

## פעולה מדויקת לבעלים

1. ב־Vercel לפתוח Project → Settings → Environment Variables. אין להעתיק ערך
   למסך, למסמך, לטרמינל או לצ'אט.
2. לערוך את `SPORTS_API_KEY` כך שהיעד היחיד שלו הוא Production. להסיר Preview
   וכל branch-specific Preview association. אם ההמרה ל־Sensitive דורשת
   remove/re-add, לקחת את הערך ישירות ממנהל הסודות/חשבון הספק, למחוק את הרשומה
   הרחבה ולהוסיף `SPORTS_API_KEY` מחדש כ־Sensitive ל־Production בלבד.
3. לוודא ש־`SPORTS_API_PROVIDER=api-football` חל על Production בלבד. ב־Preview
   להשאיר `SPORTS_API_PROVIDER=manual` מפורש או את ברירת המחדל המאושרת, ללא
   `SPORTS_API_KEY`. אין ליצור key/subscription נפרד ל־Preview ב־MVP.
4. ליצור deployments חדשים ל־Preview ול־Production; שינוי env אינו ראיה על
   deployment ישן. להשאיר את PR #14 במצב Draft ולא למזג אותו לשם הבדיקה.
5. לשמור matrix מסוננת של **שמות ו־scopes בלבד** מתוך Vercel: הפלט של
   `vercel env ls production` ושל `vercel env ls preview`, או screenshots שבהם
   values מוסתרים. הראיה חייבת להראות key ב־Production בלבד ו־provider ידני
   ב־Preview.
6. ב־Preview החדש להריץ smoke/CI במצב Manual ואת סריקת client artifacts. לבדוק
   גם שאין שם key או payload ב־runtime logs; לשמור רק PASS ומספר artifacts.
7. לאחר deploy Production מאושר, לצפות ב־Cron יחיד שמסתיים. ב־Supabase SQL
   Editor המורשה להריץ רק שאילתות מסוננות אלה (ללא token/payload):

```sql
select id, provider, status, sync_kind, started_at, finished_at, error_code
from public.sync_runs
where provider = 'api-football'
order by started_at desc
limit 3;

select provider, run_id, locked_until
from public.sync_leases
where provider = 'api-football';
```

   לקשר `id` של run מתוזמן יחיד למצב סופי עם `finished_at`, ולוודא
   `run_id is null` ו־`locked_until is null` ב־lease. לצנזר מזהים אם הראיה
   יוצאת ממאגר ההגשה. אין להציג headers, command, Vault value או provider key.
8. לצרף לכאן את matrix ה־scopes, תוצאת Preview scan/CI ותצפית Cron מסוננת.
   רק לאחר שלושתם אפשר לשנות את הסטטוס ל־`VERIFIED`.

הוראות Vercel מבוססות על התיעוד הרשמי:
[ניהול משתנים בין סביבות](https://vercel.com/docs/environment-variables/manage-across-environments)
ו־[Sensitive Environment Variables](https://vercel.com/docs/environment-variables/sensitive-environment-variables).

## ראיה מקומית שנצפתה — אינה סוגרת Hosted

נבנה Preview-equivalent במצב Manual כאשר sentinel לא־סודי הוזרק במכוון רק
כ־server variable; הסריקה מוכיחה שהקוד אינו מכניס אותו ל־artifacts. היא אינה
יכולה להוכיח את scope של Vercel או את בריאות Cron ב־Production.

```powershell
$env:PATH='<local Node.js 24 directory>;' + $env:PATH; $slice9Def025Sentinel='slice9-def025-preview-manual-sentinel-20260827'; $env:SPORTS_API_PROVIDER='manual'; $env:SPORTS_API_KEY=$slice9Def025Sentinel; npm.cmd run build; if ($LASTEXITCODE -eq 0) { $env:CLIENT_SECRET_SENTINEL=$slice9Def025Sentinel; npm.cmd run test:client-secrets }
```

```text
build: PASS — Compiled successfully
Client secret scan passed across 52 build artifacts.
```

אין regression repository שיכול להיכשל על scope מרוחק של Vercel בלי credential
וגישת owner. ה־regression המחייב של הרשומה הוא ה־matrix המסוננת + Preview
scan/Manual CI + Production Cron observation לעיל, והוא עדיין חסר במכוון.
