# S9-DEF-003 — ראיית Manual fallback ויצירה/תיקון משחק

תאריך: 27.8.2026

סביבה: Supabase מקומי בלבד ו־Playwright מול Next.js dev מקומי. לא בוצעה
קריאת Sports חיה, לא נעשה שימוש בפרויקט linked/Hosted, ולא נשמרו secret,
cookie, token, Email או payload ספק בראיה. בדיקות הדפדפן רצו ללא trace,
screenshot או video.

## החוזה שנבדק

- `ManualSportsProvider` ממפה בדיוק את `manual-catalog-v1`: שש קבוצות וחמישה
  משחקים עם UUID, season, teams, round, kickoff UTC וסטטוס זהים ל־seed. הקבוצות,
  המשחקים וה־competition הקנוני נשארים ללא provider identity.
- הגבול המורשה היחיד ל־catalog הוא
  `public.apply_manual_fixture_catalog(jsonb)`: wrapper צר
  `SECURITY DEFINER`, עם `search_path = ''`, payload בלבד ו־EXECUTE ל־
  `service_role`. אין overload מורשה שמקבל actor או clock, וה־RPC הישן
  `record_sync_attempt()` הוסר.
- ה־wrapper גוזר actor מה־header השרתִי וקורא ל־
  `private.slice9_apply_manual_fixture_catalog_core(jsonb,uuid,timestamptz)`.
  ה־core הוא `SECURITY INVOKER` ללא EXECUTE ל־PUBLIC, `anon`, `authenticated`
  או `service_role`; הוא מאמת את ה־actor, לוקח advisory transaction lock
  `2026090609`, נועל את שורת ה־actor, ליגות לפי UUID, teams ומשחקים, ומחזיק את
  ה־preflight, ה־insert, ה־run וה־audit באותה transaction.
- קריאת production מעבירה clock `NULL`, וה־core דוגם DB time טרי מיד לפני
  החלטת mutation. fixture קנוני חסר שמועדו הגיע מחזיר conflict אטומי במקום
  ליצור משחק היסטורי בלי latch. זמן מפורש וסופי זמין רק ל־owner לצורך בדיקה
  קבועה: לפני cutoff מתקבל APPLIED מלא ואחריו conflict מלא. אין test header או
  clock override ציבורי.
- כל invocation מסדי תקין יוצר בדיוק `sync_runs` סופי אחד. mutation מחזיר
  `MANUAL_APPLIED` וכותב business audit אחד; replay זהה מחזיר
  `MANUAL_NO_CHANGE` ללא audit נוסף; conflict מחזיר run
  `failed/MANUAL_CATALOG_CONFLICT` ללא mutation. קודי הצלחה הם תוצאת RPC בלבד;
  `error_code` נשאר `null` ב־succeeded.
- ה־catalog נכשל סגור מול payload לא מדויק, team או match drift, השוואת
  `short_name` כולל `NULL`, provider-owned row, latch, leaf חסר לצד conflict
  אחר, או catalog חסר בעונה עם ליגה `completed`/`archived`. prediction קיים
  לבדו אינו מפריע ל־replay מדויק.
- `ManualMatchFormBoundary` הוא Server Component שלוכד ב־inline Server Action
  את operation ואת UUID היצירה שהשרת הנפיק או match ID שקרא מהמסד. הוא קורא
  ל־`mutateManualMatch` המוגן ב־`server-only`; ה־helper מבצע session, Zod,
  הרשאת `system_admins`, gateway סגור ו־`create_or_correct_match(...)`.
  operation/match ID מהטופס אינם authoritative, ואין hidden inputs כאלה.
- create נשאר עם אותו UUID והערכים הקיימים לאחר success, ולכן לחיצה חוזרת היא
  replay; refresh מפורש מרכיב טופס חדש עם UUID חדש. correction שומר provider
  identity, מסמן manual ownership, אינו פותח latch, ומשתמש בניקוד הקנוני.
  `finished` לפני DB kickoff ו־`+/-infinity` נדחים. יצירה/תיקון שמשפיעים על
  עונה עם ליגה `completed` או `archived` נכשלות ב־
  `COMPLETED_RECONCILIATION_REQUIRED`.
- metadata של audit שומר payload מלא ובטוח ליצירה, ו־old/new bounded של
  season/team/round/kickoff/status/scores לתיקון. latch-only terminal correction
  אינה יוצרת audit definition מטעה; replay אינו מכפיל audit.

## regressions מהותיים

### pgTAP ו־dblink

- ACL ל־wrapper ול־core, actor חסר/malformed/שהוסר, actor לא־מורשה, זמן core
  לא־סופי, ו־denial ל־PUBLIC/anon/authenticated/service role.
- parity מלא לכל שדות 6/6 teams ו־5/5 matches, כולל competition ו־provider
  identity ריקים; display name אינו identity key.
- core מלא בזמן קבוע מוכיח conflict אחרי kickoff ללא row/audit חלקי ו־APPLIED
  לפני kickoff עם שני leaves, terminal run אחד ו־audit אחד.
- public actual-clock מקבל רק outcome עקבי: APPLIED עם כל ה־rows וה־audit, או
  conflict עם אפס mutation; הבדיקה אינה מסיקה cutoff מ־`started_at` או
  `finished_at`. fixture משוחזר owner-side רק לאחר בדיקת persistence.
- replay, prediction-present replay, NULL drift, round/status/provider drift עם
  leaf אחר חסר, completed, archived ו־latch בלתי הפיך; כל conflict שומר את
  הנתונים ואינו כותב business audit.
- create/replay, payload שונה לאותו UUID, finished/canceled, ציונים, correction
  replay, metadata מלא, prediction/latch identity guards ו־provider correction.
- dblink פותח sessions אמיתיות ל־`completion-vs-create` ול־
  `completion-vs-catalog`. מרוץ ה־catalog קורא ל־core המלא בזמן קבוע לפני
  cutoff, ממתין לנעילת הליגה, ואז lifecycle completion גורם conflict ושורת
  `failed/manual` סופית עם counters אפס.

### Vitest ו־Playwright

- adapter/manifest parity, payload יחיד ל־gateway, APPLIED/NO_CHANGE/CONFLICT,
  provider outage שאינו נקרא במסלול Manual, Route מסונן ו־UTC validator שדוחה
  30 בפברואר, שעה/חודש בלתי אפשריים, שנת `0000` וערכים לא־סופיים.
- `e2e/sync.spec.ts` מפעיל Cron עם leaf חסר, בודק ישירות במסד את ה־leaf וה־run
  לפני שחרור cleanup, מריץ replay מהמסך, ומוכיח שאין browser request ל־
  API-Football/API-Sports. cleanup armed מיד לאחר seed ומכסה גם כשל מוקדם.
- `e2e/scoring.spec.ts` מוכיח שאין hidden `operation`/`matchId`, מוסיף שדות
  מזויפים בשם זהה, ומוודא ישירות במסד שה־UUID הלכוד בשרת נשמר עם payload ידני
  מדויק בעוד match היעד של התוקף לא השתנה. לחיצה חוזרת נשארת replay של אותו
  UUID; תיקון terminal מנקד, משתמש רגיל נדחה, standings ו־RTL/mobile נשמרים.
