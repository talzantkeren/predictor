# S9-DEF-007 — ראיית עריכת הגדרות ליגה

תאריך: 27.8.2026

סביבה: Supabase מקומי חד־פעמי ו־Next.js production build מקומי. בדיקות
Playwright רצו מול השרת המקומי ב־Desktop Chrome וב־Pixel 5, ללא trace,
screenshot או video. לא נעשתה גישה לפרויקט linked/Hosted, לא נכתב ledger,
ולא נשמרו secret, cookie, token או Email בראיה.

## החוזה שמומש

- מנהל הליגה, או מנהל מערכת שקיבל הרשאה מפורשת, קוראים ליגה אחת בלבד דרך
  `public.get_editable_league_settings(uuid)`. ה־RPC אינו מוסיף policy רחבה
  למנהל מערכת, אינו חושף ליגות זרות ב־dashboard, ומחזיר תפקיד עורך, גרסאות,
  ניקוד, פרסי Demo, kickoff ראשון, latch וזמן מסד באותה תמונת statement.
  קישור הזמנה והניווט המלא נשארים למנהל הליגה בלבד.
- `public.update_league_settings(...)` הוא גבול `SECURITY DEFINER` צר עם
  `search_path = ''`, שמאמת payload מלא לפני נעילות, גוזר actor מ־`auth.uid()`,
  ומחזיר תוצאה אטומית עם `settings_version`, `scoring_version` ו־`changed`.
  אין UPDATE ישיר ל־`authenticated`, ואין EXECUTE ל־PUBLIC או `anon`.
- שם, תיאור, סכום והוראות Demo, מועד סגירת הצטרפות ו־late join ניתנים לעריכה
  עד completion/archive. שינוי פרטים בלבד אינו נועל matches. ליגה שהושלמה או
  הועברה לארכיון היא לקריאה בלבד.
- שינוי ניקוד או פרסי Demo נועל תחילה את שורת העונה (`FOR UPDATE`), ולכן FK
  `KEY SHARE` מסדר גם insert או העברת match לעונה; אחר כך matches ננעלים בסדר
  UUID. רק לאחר ההמתנה מחושבים kickoff ראשון ו־latch ונקרא
  `clock_timestamp()`. מעבר ל־active/completed/archived, kickoff שהגיע,
  `predictions_locked_at`, או match live/finished הם latch בלתי הפיך משותף
  לניקוד ולפרסים. match במצב `canceled` נועל רק כאשר כבר נשמר בו
  `predictions_locked_at`; הסטטוס לבדו אינו latch.
- מערכת הגרסאות דוחה stale mutation, אך replay סמנטי זהה הוא no-op זול:
  הגרסה נשארת זהה ולא נכתב audit נוסף. שתי הגשות זהות מקביליות מסתיימות
  במוטציה אחת ו־no-op אחד בלבד.
- `joins_close_at` נאכף כ־UTC סופי גם ב־Zod/RPC וגם ב־CHECK מסדי מאומת;
  שנת `0000` ו־`+/-infinity` נדחות. קלט ה־UTC הוא text מפורש התומך עד שש
  ספרות שבר, משום ש־Chromium מאפס `datetime-local` עם microseconds. שמירה של
  פרט אחר משמרת בדיוק ערך כגון `.123456`.
- הטופס שומר draft מקומי נשלט לכל השדות, checkbox, ניקוד ושורות הפרס. לכן
  reset אוטומטי של React Form Actions אינו מוחק תיקוני משתמש אחרי validation;
  גרסאות הפעולה נשמרות בנפרד בכל שגיאת validation/auth/service, והגרסה שחזרה
  מהמסד משמשת להגשה הבאה.
- `private.touch_updated_at()` משתמש ב־`clock_timestamp()`. עדכון חוקי התחרות,
  גרסאות scoring/settings, החלפת מסמך הפרסים ו־audit מתבצעים באותה transaction.

## כיסוי מסדי

`supabase/tests/league-settings.test.sql` מכסה 56 assertions: מבנה ו־ACL,
היעדר UPDATE ישיר או admin SELECT רחב, manager/admin ומקרי anonymous/member/
foreign/missing/revoked, עדכון אטומי, גרסאות ו־audit, replay/stale, מסמכי פרס
חסרים/עודפים/לא רציפים, סדר וטווח ניקוד, גבולות טקסט וקישור תשלום, גרסאות
`NULL`/לא חוקיות, UTC לא סופי/שנת אפס/microseconds, השפעת מועד ההצטרפות,
latch, status ו־completed/archive.

`supabase/tests/league-settings-concurrency.test.sql` מכסה 75 assertions עם
dblink וחיבורים מחויבים אמיתיים:

- כותבים מתחרים: winner יחיד ו־stale loser;
- שתי הגשות זהות במקביל: mutation אחד, no-op אחד ו־audit אחד;
- payload חסר נדחה לפני שורת league נעולה;
- שינוי פרטים מסתיים בזמן ששורת match נעולה;
- fixture-first ו־settings-first מוכיחים serialization דרך שורת season;
- waiter שמתחיל לפני kickoff ומוחזק מעבר לגבול קורא זמן מסד טרי אחרי השחרור
  ונדחה;
- latch שנוסף במקביל נצפה; וביטול הרשאת מנהל מערכת ממתין ל־`FOR KEY SHARE`
  ואחר כך מתקבלת דחייה אטומה.
