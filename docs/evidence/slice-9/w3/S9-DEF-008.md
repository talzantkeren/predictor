# S9-DEF-008 — ראיית החזרת ownership ידני לספק

תאריך: 27.8.2026

סביבה: Supabase מקומי בלבד ו־Playwright מול Next.js production server מקומי.
לא נעשתה קריאת Sports חיה או גישה לפרויקט linked/Hosted. לא נרשמו secret,
cookie, token, Email, סיסמה או payload ספק, ו־Playwright רץ ללא trace,
screenshot או video.

## החוזה שנבדק

- `ManualOverrideClearBoundary` הוא Server Component שלוכד את match UUID שנקרא
  מהמסד. הטופס שולח confirmation בלבד; hidden `matchId` מוזרק מהדפדפן אינו
  authoritative.
- ה־mutation מבצעת session, validation ו־exact-resource system-admin AuthZ,
  ואז gateway מסוג `server-only` יוצר service client עם actor ה־session ב־
  header פנימי. ordinary user ומנהל של ליגה זרה אינם מקבלים capability.
- `public.clear_manual_match_override(uuid)` היא `SECURITY DEFINER` עם
  `search_path = ''` ו־EXECUTE ל־`service_role` בלבד. ה־actor נגזר מה־request
  header הקבוע ונבדק שוב תחת `system_admins FOR KEY SHARE` לאחר כל המתנה.
- ה־RPC מקבלת רק match ש־`external_provider='api-football'` וה־external ID שלו
  מספרי חיובי וחסום ל־20 ספרות. row ידנית/providerless, ספק אחר וזהות malformed
  נדחים.
- סדר הנעילות הוא snapshot של season → כל ליגות העונה בסדר UUID → retain של
  actor → match מדויק → revalidation של season. מעבר ownership ממשי נכשל סגור
  אם קיימת ליגה `completed` או `archived`, עד מסירת snapshot/reconciliation
  ב־W4.
- clear ראשון משנה רק `is_manually_overridden=false` ו־`updated_at`, ומוסיף
  `match_manual_override_cleared` יחיד עם metadata חסום. status, scores,
  `result_version`, provider provenance, `predictions_locked_at` וכל שורות ושדות
  הניקוד נשמרים. replay מחזיר `result_cleared=false`, אינו מזיז timestamp ואינו
  מכפיל audit.
- שני סדרי המירוץ עם apply אמיתי ומגודר נבדקו: clear ראשון גורם ל־provider
  waiter להחיל את ה־snapshot; provider ראשון רואה override ומחזיר skip אחד,
  clear ממתין ומצליח, וה־apply הבא חוזר עם skip אפס ומחדש mutation. שני סדרי
  revocation נבדקו גם הם ללא deadlock.

## כשלים ראשונים ואבחון

הכשלים הבאים נשמרים כאבחון ואינם ראיית closure:

1. ESLint ממוקד דחה `setConfirmed(false)` סינכרוני בתוך effect. האיפוס היה
   מיותר משום שה־RSC revalidation מחליף את הטופס לאחר הצלחה; הוא הוסר וה־effect
   נשאר רק להעברת focus לשגיאת confirmation.
2. typecheck ראשון דחה literal של `BigInt` ב־E2E בגלל יעד JavaScript נמוך מ־
   ES2020, ובמקביל generated types טרם הכירו את ה־RPC החדש. מזהה fixture הוחלף
   במספר 48-bit בטוח; ה־RPC נוסף רק באמצעות generation מה־schema, בלי עריכה
   ידנית של הטיפוסים.
3. ריצת DB ראשונה: functional עבר, אך concurrency נעצרה ב־
   `permission denied for table matches`. session בתפקיד `service_role` ניסתה
   לקרוא `updated_at` ישירות לצורך assertion. הקריאה הועברה ל־test/control
   session לאחר commit; הרשאות הייצור לא הורחבו.
4. ריצת DB שנייה: functional עבר ו־29 assertions של concurrency עברו, אך
   חיבור provider הוחזר לשימוש לפני drain שני של תוצאת dblink אסינכרונית וקיבל
   `another command is already in progress`. נוסף zero-row drain מפורש אחרי כל
   אחד מחמשת ה־async results. לאחר כל כשל dblink בוצע reset מקומי נקי לפני
   ניסיון נוסף.
5. קריאת Playwright הראשונה הופעלה בטעות בלי `--env-file=.env.local` ונעצרה
   לפני זרימת DEF-008 ב־`Local Supabase configuration is unavailable`. זו
   שגיאת invocation בלבד; השרת נעצר, המסד המקומי אופס וההרצה לא נספרה.
6. ריצת Desktop הראשונה עם env תקין מצאה locator לא־ייחודי: אחרי יצירת match
   ידני נוסף, שני cards נשאו אותו צמד קבוצות. locator הוצמד ל־
   `data-manual-match-id` שהשרת הנפיק, והכותרת נשארה assertion נפרד. cleanup של
   הניסיון הכושל הושלם; רק הריצות החוזרות הירוקות נספרות.

## גבולות ו־carry ל־W4

- אין claim על Hosted/Production או provider חי. resume נבדק דרך ה־RPC האמיתי
  עם payload מקומי ומגודר בלבד.

  להתאים אותו למסלול frozen snapshots ו־reconciliation המאושר, בלי לאפשר
  provider rewrite שקט לליגה סופית.

  הוא אינו mutation, אינו מזיז timestamp ואינו מוסיף audit.
