# S9-DEF-024 — ראיית server-stream נקייה ב־E2E

תאריך הרצה: 27.8.2026  
סביבה: branch `feature/slice-9-implementation`, Supabase מקומי ו־Next.js production build מקומי. artifacts של Playwright נשארו screenshots/trace/video off ולא הודפסו credentials או payloads.

## reproduction לפני התיקון

```text
$ npm.cmd run test:e2e:run -- e2e/prediction-lock.spec.ts
Running 2 tests using 1 worker
[desktop-chromium] ... enforces the complete two-member flow with database time
[WebServer] ⨯ Error: The destination stream closed early.
[WebServer]     at ignore-listed frames { digest: '<sanitized>' }
[mobile-chromium] ... enforces the complete two-member flow with database time
2 passed (25.6s)
```

הכשל שוחזר צר ובאותו מיקום: Playwright סגר את context של desktop בזמן ש־Next.js עדיין החזיק RSC response stream פעיל. ספירת tests לבדה נשארה ירוקה.

## תיקון ורגרסיה

- `prediction-lock.spec.ts` ממתין ל־`networkidle` רק בגבול teardown, לכל חמשת הדפים, לפני סגירת page/context. אין שינוי ב־flow או ב־assertions של המוצר.
- `run-e2e.ts` לוכד את פלט Playwright המקומי ומחזיר exit 1 אם קיימת שורה מדויקת במבנה `[WebServer] … Error:`. הוא אינו מסנן או משתיק אותה; הפלט המקורי מועבר ל־stdout/stderr וה־run נכשל.
- `Playwright web-server log gate > rejects the observed closed destination stream even when tests pass` מוכיח שהמקרה המקורי מזוהה.
- `Playwright web-server log gate > allows ordinary prefixed warnings and clean passing output` מוכיח שאזהרות `Warning:` רגילות אינן מסווגות error.

```text
$ npx.cmd vitest run src/lib/playwright-server-log.test.ts

```
