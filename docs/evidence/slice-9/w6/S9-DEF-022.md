## ההיקף האוטומטי

`e2e/accessibility-matrix.spec.ts` רץ בשני פרופילי Chromium נבדלים — Desktop
Chrome ו־Pixel 5 — בכל אחד מהרוחבים 360/390/768/1024/1440. בכל רוחב נבדקו:

- ארבעת משטחי הכניסה הציבוריים `/`, ‏`/login`, ‏`/register` ו־
  `/forgot-password`;
- ארבעה משטחים מורשים עם fixture מקומי בלבד: `/admin/matches`, ‏`/admin/sync`,
  ‏`/leagues/<owned-league>/members` ו־`/leagues/<owned-league>/settings`;
- מצב שגיאת שרת אמיתי ב־members בכל רוחב: קלט שעובר validation של הדפדפן אך
  מכיל U+202E, החזרת focus ל־textarea, ‏`aria-invalid`, שני מזהי
  help+error ב־`aria-describedby`, ‏alert יחיד והישארות הבקשה במצב ממתין.

בכל route/width המטריצה מאמתת:

- axe WCAG 2 A/AA, ‏2.1 A/AA ו־2.2 AA ללא violation;
- contrast מכריע: findings של axe שניתן לחשב נבדקים כרגיל; glyph דקורטיבי
  שמסומן `aria-hidden` אינו טקסט ישים; ובמקרה שבו pseudo-element או control
  גורמים ל־axe לדווח `partially obscured`, המבחן מחשב מן ה־CSS את יחס
  foreground/background ודורש 4.5:1 לטקסט רגיל או 3:1 לטקסט גדול. finding
  אחר שנשאר בלתי־מוכרע מכשיל את הריצה;
- שם נגיש לא־ריק לכל תחנת focus מתוך accessibility snapshot;
- מעבר Tab בפועל בסדר DOM מדויק, focus בתוך viewport ו־`:focus-visible` עם
  outline או box-shadow גלוי. תחנות UA פנימיות של `datetime-local` נספרות
  כחזרות על אותו element ואינן מורשות לדלג על element או להפוך סדר;
- יעד 44×44 CSS px לכל control וקישור. ב־checkbox/radio נמדד גם ה־label
  המקושר, שהוא חלק מיעד הלחיצה התקני; אין פטור גורף לקישורי טקסט;
- `lang=he`, ‏`dir=rtl`, ללא overflow אופקי, reduced motion וללא שגיאת
  console/page.

בדיקת Vitest נפרדת מאמתת שב־loading של שני מסכי המנהל יש region יחיד בעל שם
ו־`aria-busy=true`, ללא live/status כפול ועם כיבוד reduced motion.

## כשלים אמיתיים שעלו ותוקנו

הרחבת המטריצה לא הסתפקה ב־baseline הירוק. היא הסירה פטור גורף לקישור inline
וחשפה כמה תקלות מוצר:

| finding שנצפה | תיקון |
| --- | --- |
| קישור footer של Auth היה 46×21 CSS px | נוסף `inline-flex min-h-11` |
| קישור הלוגו ל־Dashboard היה ללא שם נגיש ב־mobile | נוסף `aria-label` עברי מפורש |
| טקסט העזרה של UTC היה ביחס 4.37:1 במקום 4.5:1 | הוחלף `text-slate-500` ב־`text-slate-600` |
| skip link היה בגובה 36px | נוסף יעד `min-h-11` מיושר |
| קישורי הניווט במסכי המנהל היו בגובה 42px | נוספו `inline-flex min-h-11 items-center` |

כל הכשלים נשארו failures עד לתיקון המוצר ולריצה חוזרת. input של checkbox
שנמדד 13×16 לא היה כשל מוצר: ה־label המקושר והקליקבילי שלו גדול מ־44×44;
המבחן תוקן למדוד את יעד הלחיצה האפקטיבי. כמו כן, `datetime-local` כולל תחנות
פנימיות של מנוע הדפדפן שבהן `document.activeElement` נשאר אותו input; המבחן
מכיל אותן אך עדיין דורש רצף DOM מלא ומדויק.

## קירוב 200% — מה נעשה ומה אינו מוכיח

נוצר context חדש ונפרד בכל אחד משני הפרופילים, תוך שמירת מאפייני
user-agent/`isMobile`/touch של אותו פרופיל, עם:

```text
CSS viewport: 720x450
screen: 720x450
deviceScaleFactor: 2
physical screenshot raster approximation: 1440x900
reducedMotion: reduce
routes: 4 public + 4 authenticated + authenticated rejection error state
```

אחרי טעינת viewport metadata נצפו בדיוק `innerWidth=720`,
‏`innerHeight=450`, ‏`devicePixelRatio=2`, וכל חוזי
axe/name/order/focus/contrast/target/RTL/overflow הורצו שוב. ה־context המורשה
קיבל רק את ה־storage state של משתמש fixture מקומי; הוא לא פנה ל־Hosted או
לספק חי.

זהו קירוב reflow ו־pixel density בלבד. הוא אינו משנה את Zoom של Chrome, אינו
בודק את UI הדפדפן ואינו שווה ל־native 200%. בדיקת in-app Browser נפרדת אישרה
בקריאה בלבד שבכל חמשת הרוחבים `clientWidth=scrollWidth` ו־RTL בדף Login, אך
המשטח אינו חושף native zoom. לכן אף אחת מן התצפיות האלה אינה מסומנת כהצלחת
native 200%.
