## Checkpoint 5 — versioned match review and completed-league reconciliation

Added a forward migration that makes provider AET/PEN a durable current-version
review instead of an operator note alone. Provider replay is idempotent; an FT
correction received while review is pending updates the candidate but cannot
write the canonical result first. The fixed system-admin resolution verifies
pending/current version under `match→review` locks, applies a selected legal-time
result or cancellation, clears exactly that review, scores only non-completed
leagues and creates league-scoped reconciliation only where a frozen snapshot
already exists.

The shared scorer now preserves completed/archived predictions for provider,
manual and review-result corrections. Manual result-only correction remains
available on a completed season, while definition changes stay blocked. The
admin UI exposes server-captured review and reconciliation IDs/versions through
the existing server-only scoring gateway. Apply overwrites only the selected
snapshot and its league scores; dismiss preserves the final result. Both are
audited and reject missing actor, stale version and replay.

## Independent-review closure — boundary activation actor

Late activation discovered by a member/invite boundary is a system
reconciliation. Migration
`20260827200000_slice9_boundary_activation_actor.sql` therefore keeps one
private binding to the validated noninteractive actor. The first authenticated
Cron activation call binds it; a different administrator cannot silently
replace it, revocation cascades the binding, and the next configured Cron call
can bind the replacement. The boundary audit writes that system principal to
`audit_logs.actor_id` and keeps the real authenticated trigger only in
`metadata.triggering_actor_id`.

The lookup deliberately locks only the referenced `system_admins` row, not the
binding tuple. The multi-session regression holds a harmless update of the
binding tuple open and proves a due prediction boundary finishes before it is
released. Reintroducing a binding-row lock after the league lock would fail
that test and recreate the Cron/boundary lock inversion.
