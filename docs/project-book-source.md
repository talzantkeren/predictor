# ספר פרויקט — Predictor1

> אפליקציית Web בעברית וב־RTL לניהול ליגות פרטיות של חיזוי תוצאות כדורגל. גרסה 1.3, עודכן ב־27 באוגוסט 2026.

## מיקוד גרסת הקורס

Predictor1 הוא פרויקט הגמר בקורס טכנולוגיות אינטרנט ב־RUNI. גרסת הקורס ממוקדת בזרימה מלאה, מאובטחת וניתנת להדגמה עד 6 בספטמבר 2026. הפריסה הציבורית היא Demo בלבד: אין גביית כסף, העברת כסף, סליקה או מסמך כספי אמיתי.

## מטרת המוצר

המערכת מחליפה תהליך ידני: מנהל/ת יוצר/ת ליגה, משתף/ת הזמנה פרטית, מקבל/ת בקשות הצטרפות והוכחות תמונה מסוג Demo, מאשר/ת חברים, מפעיל/ה את הליגה ומסיים/ת אותה לאחר שכל המשחקים הגיעו למצב סופי. חברי הליגה שומרים ניחושים לפני נעילה ורואים דירוג נוכחי או סופי בהתאם למחזור החיים.

## היקף גרסת הקורס

- אימות Email, אישור חשבון, שחזור סיסמה ופרופיל בסיסי.
- ליגות פרטיות עם חוקי ניקוד ברירת מחדל 3/1/0 ותיקו כתוצאה עצמאית.
- הזמנות, בקשות הצטרפות והיסטוריית הוכחות תמונה פרטית; הוכחה אינה קבלה מאומתת.
- קטלוג משחקים ידני שתמיד עובד וסנכרון API-Football מגודר בשרת.
- ניחושים שננעלים לפי זמן מסד הנתונים ומוסתרים ממשתמשים אחרים עד הפתיחה.
- ניקוד דטרמיניסטי, תיקון תוצאה, דירוג בתחרות ושוויון במקומות 1,1,3.
- דוח מנהל לא־כספי לקריאה בלבד, עם ספירות ודירוג נוכחי או סופי.

## ארכיטקטורה

המערכת היא מונוליט מודולרי יחיד של Next.js 16 ו־TypeScript strict, נפרס ב־Vercel ומשתמש ב־Supabase PostgreSQL, Auth, Storage ו־Cron. Server Components מבצעים קריאות, Server Actions מטפלים במוטציות UI, Route Handlers מקבלים upload, Cron ו־HTTP חיצוני, ושירותי feature משותפים מחזיקים את החוקים העסקיים.

### גבולות אבטחה

- כל קלט דפדפן, URL, טופס, קובץ וספק נחשב לא־מהימן ונבדק בשרת.
- זהות המשתמש נגזרת מ־session מאומת; הרשאה נבדקת מול המשאב ו־RLS מוסיף הגנה במסד.
- כל טבלה חשופה נוצרת יחד עם RLS והרשאות מזעריות; זמן מסד הנתונים הוא הקובע לנעילה.
- הוכחות נשמרות ב־bucket פרטי, עוברות בדיקת חתימה וקידוד מחדש ל־WebP, ונגישות בקישור חתום קצר רק לאחר הרשאת משאב.
- מפתחות שרת אינם מגיעים ל־Client bundle; מפתח הספורט מיועד ל־Production בלבד והמסלול הידני נשאר ברירת המחדל ל־Local, Preview ו־CI.
- טקסט תצוגה דוחה תווי כיווניות בלתי־נראים ומוצג בבידוד כיוון מתאים.

## מחזור חיים מקצה לקצה

1. מנהל/ת יוצר/ת ליגה במצב טיוטה ומגדיר/ה עונה, ניקוד ונתוני Demo.
2. יצירת הזמנה פותחת את הליגה להצטרפות; משתמש/ת מגיש/ה בקשה והוכחת תמונה פרטית.
3. אישור אטומי יוצר חברות פעילה; דחייה שומרת היסטוריה וסיבה בטוחה.
4. מנהל/ת מפעיל/ה מוקדם דרך המוצר, או Cron קיים מפעיל אטומית לפי המשחק הראשון.
5. ניחושים נשמרים עד זמן הנעילה; תוצאות Manual או provider מניעות ניקוד דטרמיניסטי.
6. השלמה מותרת רק אחרי שכל המשחקים סופיים, מקפיאה snapshot וסוגרת בקשות פתוחות באותה transaction.
7. תיקון תוצאה אחרי השלמה נכנס ל־review ו־reconciliation מפורש בלי לשנות את הדירוג הסופי אוטומטית.

> מקור ספורט חיצוני אינו תנאי להדגמה: הנתיב הידני וה־seed הסינתטי נשארים זמינים תמיד.

## RTL, responsive ונגישות

הממשק משתמש בכיוון RTL, בטקסט לא־מהימן מבודד, ב־skip links, ביעדי מגע של 44×44 CSS px לפחות, במצבי loading בעלי שם ובשגיאות טופס מקושרות. זרימות הליבה נבדקות ב־Desktop Chrome וב־Pixel 5 ללא גלילה אופקית. בדיקת Chrome native 200% נשארת שער owner מתועד ואינה מוחלפת ב־CSS zoom.

## קריטריוני הצלחה

- הזרימה Draft → Open → Active/current → Completed/final ניתנת להדגמה דרך המוצר.
- ניחוש אינו נשמר אחרי נעילה ואינו נחשף לאחרים לפני kickoff.
- ניקוד חוזר ותיקון תוצאה נשארים דטרמיניסטיים; דירוג סופי מוקפא ומיושב במפורש.
- משתמש אינו קורא או משנה משאב של משתמש או ליגה אחרים.
- הוכחות תמונה אינן ציבוריות, אינן נשמרות גולמיות ואינן מוצגות כמסמך כספי.
- Manual fallback עובד גם כאשר ספק הספורט אינו זמין.
- תיעוד, קוד, בדיקות וגרסת ההדגמה מתייחסים לאותו candidate SHA.

## מה לא מפתחים לפני ההגשה

- כסף אמיתי, סליקה, העברה, מסמך כספי אמיתי או תפעול פרס כספי.
- אינטגרציות מודל גנרטיבי או יכולת שאינה נדרשת לזרימות הקורס.
- אפליקציה ייעודית לטלפון, צ׳אט, פיד חברתי, avatars או gamification נוסף.
- microservice, ORM, queue, cache חיצוני או ספריית state גלובלית ללא שינוי ארכיטקטורה מאושר.
