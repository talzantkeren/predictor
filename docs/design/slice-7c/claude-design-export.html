— 1. ביקורת + כיוון —
1aביקורת על העיצוב הקיים
מה עובד
  • שפת כרטיסים אחת עקבית, RTL בסיסי נכון, ללא overflow ב־390px.
  • DemoNotice קיים ומנוסח היטב; המידע נאמן לנתונים האמיתיים.
  • מבנה הדפים כבר תואם את הנתיבים — הבעיה היא הצגה, לא מבנה.
מה יוצר בלבול
  • אין היררכיה: ברכת "שלום" תופסת רבע מסך בעוד הפעולה האמיתית (ניחושים פתוחים, בקשות ממתינות) לא מוצגת כלל. "יצירת ליגה" מופיע פעמיים באותו מסך.
  • המשחק הבודד הוא היחידה: כל משחק — כרטיס ענק עם CTA כחול ראשי. שישה כפתורים ראשיים במסך אחד = אף אחד אינו ראשי. אין תחושת "כמה נשאר לי במחזור".
  • שקילות חזותית: "GMT+3 Asia/Jerusalem" באותו משקל כמו שמות הקבוצות; המפריד "–" מרחף בלי תוצאה.
  • bidi שבור: שורות זמן מערבבות עברית/לטינית/מספרים וקופצות; שמות ליגה לטיניים מיושרים לא עקבית.
  • דירוג: הטבלה צפה בדף ריק, שוויון 1,1 מוצג בלי הסבר, אין הדגשת המשתמש הנוכחי, ואין עמודה ממוינת מסומנת.
  • נגישות: סטטוסים נבדלים בצבע רקע בלבד; אין ניווט פנימי (tabs) בתוך ליגה — כל מעבר הוא "חזרה" וכניסה מחדש.
  • צפיפות: מובייל מציג כרטיס וחצי למסך; padding כפול (כרטיס בתוך כרטיס) מבזבז רוחב יקר ב־390px.
1bהכיוון המומלץ — "לוח המחזור"
P1
Sports Command Center בהיר · יחידת הארגון היא המחזור
כיוון יחיד. וריאציות רק בפרטים, לא בשפות מתחרות.

למה זה הכיוון הנכון: המוצר חי במקצב שבועי — מחזור נפתח, ננעל, מנוקד. הבלבול הנוכחי נובע מכך שה־UI מסודר סביב משחקים בודדים וכרטיסים שקולים. ארגון סביב המחזור נותן למשתמש תשובה אחת ברורה בכל כניסה: מה נשאר לי לנחש ומתי זה ננעל — בלי להמציא נתון אחד חדש.

Moodboard מילולי: דף מערכת של שבת אחר הצהריים · טופס ניחושים נקי על נייר לבן · לוח תוצאות עירוני כהה אחד בלב המסך · עט ירוק שמסמן "בוצע".

עקרונות חזותיים
  1. נייבי = זהות, מסגרת וניווט. אמרלד = פעולה, שמירה והתקדמות — ורק הם.
  2. משטח כהה יחיד וסמנטי: "לוח המשחק המרכזי" (scoreboard). כל השאר בהיר.
  3. מספרי תוצאה גדולים, ממוסגרים, ברוחב אחיד — תוצאה תמיד בית–חוץ, בית תמיד ראשון מימין.
  4. סטטוס = צורה + מילה + צבע (● פתוח, ✓ נשמר, ▪ נעול, ◆ הסתיים, ! נדחה, ✕ בוטל).
  5. צפיפות עיתונאית: שורת משחק במקום כרטיס משחק. RoundCard אחד = מחזור שלם.
מה מבדיל את זה מ־Dashboard גנרי

רכיב חתימה RoundCard שנראה כמו טופס מחזור ולא כמו רשימת כרטיסים; לוח כהה אחד שמרגיש "אצטדיון" בלי תמונות; מונוגרמת ליגה טיפוגרפית במקום אווטרים; ושפת ניקוד 3/1/0 קבועה שחוזרת בכל מסך. טיפוגרפיה: Heebo — עברית־ראשונה, משקלים כבדים למספרים (כפוף לבדיקת עברית/לטינית/ספרות באבטיפוס זה).

1mרכיבים חוזרים + מיפוי למסכים
AppShell — topbar לבן 56/60px: מונוגרמה+שם מימין, ניווט ראשי, פרופיל/התנתקות בקצה. אין sidebar. מובייל: ללא bottom-nav (אין נתיבים גלובליים מספיקים). RTL: הלוגו תמיד בקצה הימני. a11y: skip-link, ‎nav עם aria-label.
Navigation (LeagueTabs) — tabs בתוך ליגה: סקירה/משחקים/דירוג + חברים/הגדרות למנהל בלבד. פעיל = משקל 700 + קו תחתון נייבי (לא צבע בלבד). מובייל: גלילה אופקית עם fade, יעד מגע 44px. מקלדת: חצים בין tabs.
PageHeader — מונוגרמה, כותרת, שורת הקשר (תחרות · עונה), chips סטטוס+תפקיד, פירור "‹ הליגות שלי". שם ארוך: ‎break-words, לעולם לא חותך מידע קריטי.
LeagueCard — שם, עונה, StatusBadge, chip תפקיד, שורת מצב מחזור. variants: רגיל / ריק / שגיאה. hover: גבול נייבי + shadow-md. הכרטיס כולו קישור אחד.
RoundCard ★ רכיב חתימה — כותרת מחזור, נעילה ראשונה, פס התקדמות מקטעי (מחושב רק ממשחקי המחזור המוצגים) + "נוחשו X מתוך Y", ורשימת MatchRow. variants: פתוח / נעול חלקית / הסתיים / מעורב. הפס = ‎role="img" עם aria-label טקסטואלי.
MatchRow — שורה אחת למשחק: StatusBadge+מועד, בית–חוץ (בית תמיד ראשון מימין), ScoreInput או תוצאה, מטא ופעולה. states: פתוח / נשמר / נעול / הסתיים+נקודות / נדחה / בוטל. דסקטופ: grid 4 עמודות; מובייל: נערם. תוצאה רשמית — קופסה כהה (הלוח הסמנטי בזעיר).
ScoreInput — ‎44×44, ‎inputmode="numeric", ערך 0–99, בית ואז חוץ. states: ריק / מלא (גבול אמרלד) / disabled / locked / שגיאה. תווית aria: "שערים — הפועל תל אביב". הספירה לאחור עזר בלבד — הנעילה בשרת.
StatusBadge — צורה+מילה+צבע: ● פתוח / ✓ נשמר / ▪ נעול / ◆ הסתיים / ! נדחה·ממתין / ✕ בוטל·נדחתה. לעולם לא צבע בלבד; קריא גם בגווני אפור.
StandingsTable / StandingsCard — טבלה מ־768px ומעלה, שורות־כרטיס מתחת. ריבוע מקום (נייבי מלא ל־1), tag "שוויון", chip "את/ה" + רקע וסימן קצה לשורת המשתמש. עמודת מיון מסומנת ▼. מספרים tabular-nums.
EmptyState / ErrorState — מסגרת מקווקוות + כותרת + פעולה אחת; שגיאה: ✕, ניסוח מה קרה + "ניסיון חוזר", ‎role="alert".
DemoNotice — פס ענברי קבוע עם ◆ בכל אזור כספי; לא נסגר ולא נעלם. אסמכתא: metadata + כפתור צפייה מפורש, ללא thumbnail.
Skeletons — צורות בגודל הרכיב האמיתי (RoundCard, טבלה, כרטיסים); ללא shimmer ב־reduced-motion; ‎aria-busy על האזור.

ההחלטות החשובות
  1. המחזור הוא יחידת הארגון — RoundCard מחליף את רשת כרטיסי המשחק; ההתקדמות מחושבת רק ממשחקי המחזור שמוצגים.
  2. אמרלד = פעולה בלבד — כפתור ראשי אחד לכל אזור. נייבי = זהות וניווט. זה מה שמחזיר היררכיה.
  3. משטח כהה אחד סמנטי — לוח "המשחק הקרוב" ותוצאה רשמית בלבד. אין Dark Mode.
  4. סטטוס = צורה+מילה+צבע — מערכת אחת לכל המוצר (משחק, בקשה, ליגה).
  5. tabs בתוך ליגה — במקום "חזרה לליגה"; נתיבים קיימים בלבד, חברים/הגדרות למנהל.
סיכונים ונקודות להחלטה
  • ל־Heebo אין ספרות tabular אמיתיות בכל המשקלים — מספרי תוצאה יושבים בקופסאות ברוחב קבוע; לאשר אחרי בדיקת ספרות מול עברית.
  • 5 tabs ב־390px גלישים אופקית — לאשר את דפוס הגלילה־עם־fade או לקצר תוויות.
  • ניסוח הספירה ("בעוד 54 ימים ו־4 שעות") ארוך בעברית — הוחלף ב"נעילה: [מועד]" + ספירה רק ביממה האחרונה. דורש אישור.
  • ה"פעולה הבאה" בלוח האישי נגזרת מנתונים קיימים (ניחושים חסרים, בקשות ממתינות) — אין נתון חדש, אבל דורשת query מצרפי קטן ב־dashboard. לאשר.
תוכנית implementation (Next.js 16 · Tailwind · RSC)
  1. Tokens: הרחבת globals.css ב־@theme (צבעים, radius, shadow, font Heebo דרך next/font) — בלי ספריית UI.
  2. שלד: AppShell + LeagueTabs + PageHeader כ־Server Components תחת src/components/; החלפת ה־header הקיים ב־(app)/layout.tsx.
  3. מסכים לפי סדר: matches (RoundCard, MatchRow, ScoreInput — הרכיב היחיד עם client state) ← dashboard ← league ← standings. אותם queries, אותם routes, אותן הרשאות.
  4. מצבים: Skeletons ב־loading.tsx הקיימים, EmptyState/ErrorState משותפים.
  5. QA: בדיקת 390/768/1440, מקלדת, ניגודיות AA, reduced-motion, וה־e2e הקיימים ללא שינוי selectors התנהגותיים.
